# Acceptance Criteria

The parent program is acceptable when:

- every required churn class is assigned to a producer-owned child packet;
- every child identifies target surfaces, producer owner, problem, solution, guardrails, validation gates, and measurable success criteria;
- every child requires producer entrypoint inventory before implementation readiness;
- every child identifies applicable common metrics from `resources/metrics.md`;
- every child documents external dependencies or states that none exist beyond the parent sequence;
- the parent distinguishes core packets, external dependencies, and optional adjacent evidence-retention work;
- the churn-class table covers generated, effective, validation, operational, host projection, and source-trigger surfaces;
- no parent artifact authorizes implementation, generated output edits, retained evidence deletion, or cleanup;
- no child duplicates existing dependency packets;
- parent program structure validation can pass without nesting child packets under the parent.
