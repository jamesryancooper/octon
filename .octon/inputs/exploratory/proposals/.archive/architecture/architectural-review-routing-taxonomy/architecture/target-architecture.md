# Target Architecture

## Routing Matrix

| Situation | Route |
| --- | --- |
| Architecture proposal before acceptance | Pre-Integration Architecture Review |
| Source or concept needs packetization into revised architecture | Architecture Revision Packet |
| Implemented change needs architectural evidence after promotion | Post-Integration Architecture Review |
| Durable mechanism needs current architecture review | Current-State Mechanism Architecture Review |
| Whole harness or bounded domain readiness question | Architecture Readiness Audit |
| Existing domain path critique | Domain Architecture Audit |
| Existing durable surface critique | Surface Architecture Audit |
| Completed lifecycle run evaluation | Lifecycle Postmortem Evaluator |
| Constitution, precedence, fail-closed, ownership, or authority conflict | Constitutional Challenge |

## Routing Rules

- Exactly one primary route is selected.
- Secondary routes may be recorded as evidence-only support.
- Constitutional challenge supersedes architectural review when normative
  authority is in conflict.
- Architecture Revision Packet remains extension-owned packetization support.
- Lifecycle postmortem output remains retained evidence and cannot authorize
  lifecycle mutation.
