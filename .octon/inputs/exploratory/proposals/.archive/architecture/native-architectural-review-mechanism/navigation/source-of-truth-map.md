# Source Of Truth Map

## Proposal-Local Lifecycle Sources

- `proposal.yml` defines the parent program identity, scope, child list,
  promotion target envelope, and lifecycle posture.
- `architecture-proposal.yml` defines the architecture subtype decision.
- `resources/child-packet-index.yml` is the parent-owned child registry and
  dependency graph.
- `architecture/packet-sequence.md`, `architecture/child-packet-contract.md`,
  and `architecture/program-closeout-plan.md` define program sequencing and
  parent-child boundaries.

## Durable Authority After Promotion

## Retained Evidence

The target mechanism retains review reports and support receipts under
mode-specific evidence roots proposed by child packets. Review reports are
evidence unless a durable lifecycle contract gates on their schema-backed
support receipt.

## Derived Projections

Generated proposal registries, artifact indices, skill projections, capability
indices, and host projections are derived-only. They are refreshed by existing
publication scripts and cannot replace manifests, workflows, schemas, or
validator contracts.

## Raw And Proposal Inputs

Raw source material, extension prompt bundles, proposal packets, parent program
summaries, generated prompt helpers, chat, host state, dashboards, tool
availability, and model memory are not authority.

## Boundary Rule

Parent program artifacts coordinate. Child packets decide their own durable
targets and evidence. No parent artifact satisfies child implementation,
conformance, drift/churn, promotion, closeout, or archive receipts.
