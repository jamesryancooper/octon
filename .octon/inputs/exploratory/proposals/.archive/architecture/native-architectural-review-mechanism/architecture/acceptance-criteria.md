# Acceptance Criteria

The program is accepted only when the child packets collectively satisfy these
criteria.

## Program Structure

- The parent program validates with `validate-proposal-program-structure.sh`.
- Every child packet is a sibling proposal under the canonical architecture
  proposal path.
- The child registry lists all child IDs, paths, dependencies, write scopes,
  rollback posture, and readiness requirements.
- Parent artifacts contain no child-owned authority fields or child receipt
  substitutes.

## Native Mechanism Completeness

- Native doctrine exists for the Balanced Architecture Review Method.
- A canonical naming model exists for display names, slugs, workflow directory
  names, schema names, contract names, validator names, evidence roots, support
  artifacts, and legacy aliases.
- Review mode routing is deterministic and validator-backed.
- Strict schemas exist for architectural review reports, routing decisions, and
  support receipts.
- Native workflows exist for pre-integration, post-integration, current-state
  mechanism, and architecture-readiness review.
- Skills and commands invoke workflows without duplicating authority.

## Lifecycle Gate Completeness

- Architecture proposal acceptance and implementation authorization fail closed
  unless a fresh passing Pre-Integration Architecture Review receipt is present.
- Support receipts reject missing evidence refs, omitted validators, stale
  digests, placeholder text, ambiguous prose-only results, unresolved blockers,
  and passing verdicts without mode-specific coverage.
- Implementation conformance and post-implementation drift/churn remain hard
  closeout gates.
- Post-Integration Architecture Review remains evidence-only unless later
  policy explicitly selects it as a gate.

## Naming And Migration

- `architecture-readiness-audit` is canonical.
- `architecture-readiness-audit` has only a bounded migration window and a
  validator-enforced retirement condition.
- Related review names use a consistent noun phrase pattern, such as
  Pre-Integration Architecture Review and Current-State Mechanism Architecture
  Review.

## Extension Split

- `octon-concept-integration` references native doctrine after promotion.
- Architecture Revision Packet remains extension-owned as a packetization
  helper.
- Duplicate method ownership is removed after native doctrine lands.
- Extension validation proves prompt routes do not claim native gate authority.

## Validation

- Existing proposal validators pass for the parent and child packets.
- New architectural-review semantic validators are specified by child packet
  before the lifecycle gate wiring phase.
- Generated proposal registry and compact artifact indices are regenerated by
  scripts and validate as derived outputs.
