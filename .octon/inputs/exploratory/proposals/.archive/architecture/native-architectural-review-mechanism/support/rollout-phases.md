# Rollout Phases

1. Create parent and child proposal packets.
2. Review and accept the parent program.
3. Review and accept Phase 1 child packets.
4. Implement doctrine, naming, routing, schemas, and receipt validators.
5. Implement workflows and thin invocation surfaces.
6. Wire proposal lifecycle gates after strict receipts exist.
7. Preserve closeout boundaries and add mechanism index entry.
8. Align extension prompts and retire confusing aliases.
9. Run validators, negative controls, publication scripts, and generated
   projection checks.
10. Close child packets, then close the parent program.

## Rollout Guardrails

- No lifecycle gate wiring before strict receipt validation.
- No permanent `architecture-readiness-audit` compatibility route.
- No post-integration review hard gate in the initial rollout.
- No generated or proposal-local artifact becomes authority.
