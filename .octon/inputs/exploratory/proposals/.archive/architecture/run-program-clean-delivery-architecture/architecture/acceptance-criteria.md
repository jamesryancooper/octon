# Acceptance Criteria

- The design chooses wrapper/profile composition unless a concrete gap proves a
  new route is required.
- Every route transition names an owning lifecycle, workflow, skill, helper, or
  validator.
- The design explicitly rejects parent evidence substitution for child
  authority.
- The design explicitly rejects local/private evidence as hosted/shared
  closeout proof.
- Stop conditions are machine-checkable.
- Promotion targets are file-level or explicitly excluded, and each target has
  current assumption, required delta, owner, priority, and rationale.
- Additive extension source changes are bound to generated effective
  publication, generation-lock freshness, publisher ownership, and raw-input
  non-authority.
- Validators, fixtures, retained evidence roots, rollback route, and closeout
  refusal criteria are named precisely enough for implementation to start
  without inventing missing scope.
- A strict pre-integration architecture review receipt exists, passes, and is
  fresh for the packet digest.
- Later review must still return `accepted` before implementation prompt
  generation or durable target mutation is authorized.
