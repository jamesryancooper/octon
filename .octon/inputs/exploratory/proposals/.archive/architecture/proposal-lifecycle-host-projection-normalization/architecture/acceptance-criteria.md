# Acceptance Criteria

- A complete naming matrix covers proposal packet lifecycle, proposal program
  lifecycle, delivery, closeout, and cleanup surfaces.
- Codex, Claude, and Cursor projection differences are either eliminated or
  explained by manifest-backed support rationale.
- Canonical operator commands are symmetric for packet and program routes where
  the underlying lifecycle capability is symmetric.
- Compatibility aliases are documented as aliases and do not create independent
  authority.
- Host projection files are generated from source and pass projection parity
  validation.
- Generated/effective projections remain derived-only and are not cited as
  runtime, policy, support, or closeout authority.
- Route ids, workflow ids, receipt schemas, and prompt-set ids are not renamed
  without a separate compatibility and migration plan.
