# Implementation Plan

1. Inventory proposal lifecycle command and skill projections across source
   manifests, runtime capability manifests, generated/effective routing,
   product catalog entries, and Codex, Claude, and Cursor host directories.
2. Classify every surface as canonical operator command, compatibility alias,
   internal route id, workflow-backed route, prompt-backed route, generated
   projection, or host-specific omission.
3. Define the naming matrix and host adapter support policy for proposal packet
   lifecycle, proposal program lifecycle, packet delivery, program delivery,
   terminal closeout, Change closeout, worktree closeout, repo hygiene cleanup,
   and lifecycle-residue cleanup.
4. Update source manifests and docs only after review acceptance. Do not edit
   `.codex`, `.claude`, or `.cursor` as authored sources.
5. Preserve existing aliases unless a compatibility-retirement plan is accepted
   with validation and operator-facing documentation.
6. Republish generated/effective and host projections through the canonical
   publication flow.
7. Add or tighten validators that prove host projection sets, hashes, titles,
   host adapter declarations, and route-to-command mappings match the accepted
   naming matrix.
