# Acceptance Criteria

- An operator can request proposal-program clean delivery through one explicit command or wrapper.
- The runner can emit a route graph before executing routes.
- Bare proposal-program lifecycle runs remain handoff-only unless explicitly changed by accepted policy.
- Review and revision loops are visible in plan output.
- Architecture-review requirements are visible before they block delivery.
- `target_outcome=cleaned` remains a request, never a claim.
- Child receipts and child authority remain child-owned.
- Delivery, closeout-change, closeout-worktree, and repo-hygiene authority boundaries remain intact.
- Regression fixtures cover parent review loop, child review loop, architecture-review refresh, implementation, closeout, archive, delivery, Change closeout, cleanup proof, blocked state, and resume.
