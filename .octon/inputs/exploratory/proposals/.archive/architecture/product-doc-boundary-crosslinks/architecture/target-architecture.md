# Target Architecture

Product documentation should help readers move from product features to
architecture/governance mechanism docs without confusing authority.

Target posture:

- product docs use `product features`;
- architecture and governance docs use `governed cross-surface mechanisms`;
- runtime/operator docs use concrete runtime terms;
- the product feature catalog stays navigation-only;
- product feature pages link to the mechanism index for authority-class,
  evidence, runtime, workflow, route, state machine, generated, input, and
  ownership detail;
- product docs do not turn lower-level runtime/operator mechanisms into product
  features unless a future authoritative product contract says so.
