# Target Architecture

The corrective architecture is a seven-child proposal program that turns the
postmortem findings into explicit runtime and workflow changes:

1. Compact blocker remediation and artifact budgets constrain recoverable
   blocker retries by repeated fingerprint, file count, and byte size.
2. Autonomous hygiene continuation resolves recoverable closeout ambiguity by
   running the narrowest target-owned preserve/exclude route and then
   continuing the lifecycle.
3. Stale local branch retirement proves no unique commits, no protected state,
   and no unresolved upstream/PR ownership before switching away from and
   deleting stale local branches.
4. Run-health localization keeps speculative generated projections in scratch
   or local-private state and promotes only route-owned final evidence.
5. No-dispatch deduplication records repeated resumptions in one bounded
   attempt ledger when inputs and blocker fingerprints have not changed.
6. Retained-state final reporting names every delivered, retained, deleted,
   local-private, and manual-review class so cleanup scope cannot be overclaimed.
7. Authorized hosted landing consumes current no-PR authorization receipts
   non-interactively after receipt, provider, rollback, final-sync, and
   execution-environment approval-lane checks are bound.

## Authority Model

The parent program coordinates ordering only. Each child packet owns its own
promotion targets and retained evidence. Proposal Program Delivery owns
aggregate delivery receipts. Change closeout owns Git landing, sync, branch
cleanup, and terminal proof. Worktree hygiene routes own classification,
preserve/exclude, and cleanup authorization. Generated output publishers own
promotion and freshness receipts for generated read models.

## Autonomous Continuation Model

Recoverable blocker classes such as `artifact-ownership-unclear`,
`worktree-hygiene-blocked`, stale hygiene fingerprints, foreign/ambiguous
closeout residue, artifact-budget breaches, stale local branches with no unique
commits, and diagnostic output churn should route into narrower governed
recovery paths. The lifecycle pauses only when the route cannot classify or
preserve the risk, lacks authority for destructive or external action, hits a
protected ref or policy conflict, requires unavailable credentials, or receives
conflicting operator instructions.

## Terminal Claim Model

`implemented` child lifecycle evidence cannot imply `git_clean_terminal`,
branch retirement, hosted landing, archive authorization, or generated-output
freshness. Terminal claims require fresh delivery receipt validation, Change
closeout alignment, live ref proof where applicable, exact residue disposition,
and final current-state proof after the last mutation.
