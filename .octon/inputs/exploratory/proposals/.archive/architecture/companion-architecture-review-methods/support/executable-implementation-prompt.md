## Workstream A — Author The Four Companion Method Docs

Use `greenfield-reference-architecture-review-method.md` as the authored
template for shape and tone. Each `<slug>.md` must contain, in order:

1. **Method question** (title banner) with a one-line non-authority framing that
   foreshadows the fail-closed output boundary.
2. **Use Cases And Non-Goals** — when to select the method and what it explicitly
   does not do, naming the sibling method or audit that owns each excluded job
   (per `resources/method-taxonomy-companions.md` §§3–6).
3. **Required Inputs** — what a review of this method cannot start without.
4. **Lens Profile** — a pointer to `lens-bank.yml#method_profiles.<slug>`, citing
   lens ids only, listing the **exact** required and optional lens sets from that
   profile, and asserting **"no private lens catalog"**. The listed sets must
   match `lens-bank.yml` verbatim (see the frozen lens sets below).
5. **Required Output Sections** — the method's output contract, each output
   mapped in brackets to the named lenses from the profile that drive it.
6. **Escalation Rules** — cite `review-routing.yml` `method_selection`
   (`escalation_map`, `constitutional_conflict_routes_to`); do not restate
   routing as new authority.
7. **Output Boundary (Fail-Closed)** — output is retained evidence or proposal
   input only, never lifecycle-gate or implementation authority; the
   pre-integration architecture review support receipt remains the only
   lifecycle-gating review artifact.
8. **Related / Navigation** — navigation-only links to `naming.yml`,
   `architecture-lens-bank.md`/`lens-bank.yml`, `review-routing.yml`, and the
   Balanced default.

### Per-method output contracts (AC-1..AC-4)

- **Tradeoff** — option matrix; quality-attribute assessment; per-option
  tradeoff/risk/reversibility analysis; recommendation with rejected
  alternatives; ADR-ready decision-record input with revisit triggers.
- **Failure-Mode** — failure-mode catalog (authority inflation, stale evidence,
  generated-output misuse, bypass paths, partial execution, zombie runs,
  rollback gaps, operator confusion); per-mode detection/containment; recovery
  posture; required validators or negative controls; unresolved-failure blocker
  list.
- **Evolution/Fitness** — architectural fitness functions; drift triggers;
  retirement triggers; compatibility posture; validator needs; revisit cadence
  with owner.
- **Boundary/Authority** — actual-vs-claimed authority map;
  accidental-control-surface findings; containment plan (what must move into
  `framework/**` or `instance/**`, what must be demoted to evidence or
  projection); fail-closed and support-claim implications; blocker list.
