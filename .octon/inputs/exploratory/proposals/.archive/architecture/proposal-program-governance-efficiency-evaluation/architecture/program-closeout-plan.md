# Program Closeout Plan

Parent closeout is allowed only after every required child reaches an allowed terminal outcome through its own lifecycle route.

## Required Child Outcomes

- `proposal-governance-efficiency-report-contract` must close with child-owned evidence that the advisory report contract is stable and non-authoritative.
- `proposal-governance-efficiency-evidence-collector` must close with child-owned evidence that collection is read-only and cites retained evidence by reference.
- `proposal-governance-efficiency-scoring-and-classification` must close with child-owned evidence that scoring is deterministic where possible, uncertainty is explicit, and recommendations remain advisory.
- `proposal-governance-efficiency-operator-surface` must close with child-owned evidence that the command or skill surface does not become a required lifecycle gate.
- `proposal-governance-efficiency-validation-and-documentation` must close with child-owned validation and docs proving advisory-only behavior and authority boundary preservation.

## Aggregate Parent Evidence

Before parent archival, parent-local aggregate receipts must show:

- parent program structure validation passed;
- child registry, human index, sequence, child contract, and closeout plan remained synchronized;
- every required child terminal outcome is current and child-owned;
- advisory reports do not satisfy review, validation, closeout, cleanup, archive, or terminal proof;
- recommendations that would change governance policy are routed to later proposals.

## Refusal Conditions

Refuse parent closeout or archive when:

- any required child remains non-terminal without explicit deferral, rejection, supersession, or replacement evidence;
- a parent artifact attempts to satisfy a child receipt or child validation verdict;
- the evaluator is used as a delivery gate without a later accepted proposal;
- missing evidence is treated as a confident recommendation;
- automation or batching recommendations would weaken authority boundaries.
