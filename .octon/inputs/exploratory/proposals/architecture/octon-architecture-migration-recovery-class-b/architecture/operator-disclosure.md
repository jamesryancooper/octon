# Operator Experience And Disclosure

## Normal Experience

The operator states intent, not route mechanics. Healthy Class A and admitted
Class B work completes or opens the deterministic protected PR without routine
questions. A single status screen shows class, immutable route digest,
attempt/outcome, attribution strength, dependency health, preserved candidate,
next automatic action, and freshness.

## Outcome Vocabulary

- `attempt_performed`: authenticated evidence binds the provider effect to this
  exact attempt.
- `state_satisfied`: desired provider state exists, but this attempt is not
  proven causal; no retry and no performed claim.
- `not_performed`: provider evidence proves this attempt made no effect; a new
  attempt still requires fresh authority.
- `failed`: definitive attempt-bound failure without ambiguous remote effect.
- `unknown`: outcome is unresolved and retry is prohibited while automated
  reconciliation continues.
- `manual_intervention`: bounded probes cannot decide safely; one operator
  judgment is required.

These are per operation/attempt. Octon does not claim universal exactly-once or
atomic SQLite/provider commit.

## Failure Experience

The status surface names the failed dependency, affected consequence, exact
observations, candidate/evidence preserved, next automatic probe/restart, and
one repair route. Provider/broker/verifier/store/signer/evidence outages do not
expose credentials, discard candidates, or generate repeated prompts.

ROD-002 permits one concise actionable choice only for irreducible ambiguity.
It never offers blind retry, unsigned fallback, stale authority, lower class,
or PR laundering.

## PR Disclosure

Protected PR means valid work was ineligible for automatic no-PR under the
frozen predicate. It does not mean authority was invalid or that an unknown
effect was safely retried. The PR binds the exact candidate/verdict/evidence and
is itself reconciled if creation/update response is lost.

## Continuous Operation Disclosure

Scheduled maintenance uses existing mission/Run Contract controls with bounded
time, concurrency, probes, pause, revocation, evidence, and closeout. The
proof effect is disposable and reversible; production and trust-root targets
are not supported by RP-08.

## Unsupported Remainder

RP-08 does not claim universal exactly-once, provider/SQLite atomicity,
causation from state equality, automatic resolution of all unknowns,
production trust-root automation, arbitrary providers/action classes,
unbounded recurring autonomy, or full two-project/30-day solo acceptance. The
last remains RP-14/UE-014.
