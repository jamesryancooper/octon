# Acceptance Criteria (Program Level)

Acceptance of this parent program means the coordination structure is
approved — not any child's content. The program is acceptable when:

1. The child registry declares all seven children with canonical sibling
   paths, phases, dependencies, gates, write scopes, and required flags, and
   `related_proposals` matches the registry exactly.
2. The sequence encodes the only hard dependency found in the evidence
   (`evidence-classification-v2-migration` after
   `retained-evidence-operability-contract`) and declares the remaining
   ordering as pacing, not gating.
3. Every finding F-03 through F-10 maps to exactly one child; F-01/F-02 are
   explicitly excluded as owned by the sibling override packet; no finding is
   silently dropped.
4. The child contract binds children to independent validity, own receipts,
   validation floors (negative controls where enforcement is touched),
   write-scope discipline, and allowed terminal outcomes.
5. The closeout plan requires aggregate evidence outside proposal paths and
   resolves or re-defers the source review's open questions 2, 3, 4, and 7.
6. The conditional child (F-10) has an explicit no-action closure route so
   the program cannot stall on a decision that may legitimately be "not now".
7. Program validators pass: base proposal standard, program structure, and
   input non-authority.

Child acceptance criteria are defined per child at child creation; this
parent never substitutes for them.
