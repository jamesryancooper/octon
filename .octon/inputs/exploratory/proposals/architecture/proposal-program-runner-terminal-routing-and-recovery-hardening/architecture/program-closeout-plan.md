# Program Closeout Plan

Program closeout is allowed only after every required child satisfies the
active proposal-program closeout policy.

For the current authored policy, required non-deferred children must become
`archived` or `rejected`. Implemented status alone is not terminal for parent
closeout. Archived children must provide fresh child-owned implementation,
conformance, drift/churn, and proposal-closeout receipts with archive
authorization. Rejected children must provide fresh rejected review evidence.

The parent closeout route may cite aggregate controller evidence and
child-owned receipts. It must not synthesize child receipts or archive children.

Blocked closeout or archive must produce machine-readable evidence with route,
child or parent target, blocker class, freshness state, hygiene state, and next
route condition.
