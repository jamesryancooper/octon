## Findings Addressed

### AR-002 — Promotion targets must match the parent registry write scopes exactly

**Previous position.** `proposal.yml#promotion_targets` used two directory-level
scopes (`.octon/framework/constitution/contracts/retention/`,
`.octon/framework/cognition/_meta/architecture/`) and one broad script
directory (`.octon/framework/assurance/runtime/_ops/scripts/`), and omitted the
child evidence root. `target-architecture.md` repeated the same directory-level
work areas, and neither architecture doc named the four new deliverable files.

Superseded `promotion_targets` value:

```yaml
promotion_targets:
  - ".octon/octon.yml"
  - ".octon/framework/constitution/contracts/retention/"
  - ".octon/framework/orchestration/runtime/_ops/scripts/write-run.sh"
  - ".octon/framework/cognition/_meta/architecture/"
  - ".octon/framework/assurance/runtime/_ops/scripts/"
```

**Revised position.** `promotion_targets` now lists the exact deliverable files
from the parent registry write scopes
(`octon-public-distribution-model/resources/child-packet-index.yml`, child
entry `public-distribution-local-storage-evidence`) plus the child evidence
root:

```yaml
promotion_targets:
  - ".octon/octon.yml"
  - ".octon/framework/constitution/contracts/retention/local-private-evidence-v1.schema.json"
  - ".octon/framework/constitution/contracts/retention/repository-git-posture-v1.yml"
  - ".octon/framework/orchestration/runtime/_ops/scripts/write-run.sh"
  - ".octon/framework/cognition/_meta/architecture/hosted-repository-footprint.md"
  - ".octon/framework/assurance/runtime/_ops/scripts/validate-local-storage-policy.sh"
  - ".octon/state/evidence/validation/proposals/public-distribution-local-storage-evidence/"
```

`target-architecture.md` File-Level Work Areas now names each registry-scoped
deliverable file with its role and marks the four new deliverables
(`local-private-evidence-v1.schema.json`, `repository-git-posture-v1.yml`,
`hosted-repository-footprint.md`, `validate-local-storage-policy.sh`)
explicitly, and Proposed Components ties components to those filenames.
`implementation-plan.md` phases 1-4 now name the deliverable file each phase
produces or modifies.

**Why this improves alignment.** Parent child-packet-contract item 11 requires
promotion targets to be the exact registry write-scope deliverables plus the
child evidence root. File-exact targets remove ambiguity about which files this
packet may create or modify under the broad `contracts/retention/`,
`cognition/_meta/architecture/`, and `assurance/_ops/scripts/` directories,
prevent silent scope widening at implementation time, and make promotion-gate
verification deterministic.

### AR-011 — AC-01 must enumerate the exact roots covered

**Previous position.** AC-01 read:

> Every major .octon root, input subtype, host projection, log, cache, archive,
> report, and release artifact has one explicit default Git posture plus
> bounded exceptions.

"Every major .octon root" was unverifiable because no root list existed;
an implementation could satisfy the sentence while skipping any root.

**Revised position.** AC-01 now enumerates the exact roots the posture matrix
must cover at minimum: `.octon/state/` (including `.octon/state/evidence/` and
operational runtime state), `.octon/generated/`, `.octon/inputs/` with
per-subtype posture for raw intake, archives, extension source, ideation,
proposals, plans, syntheses, and reports, and repository host projections
(`.claude/`, `.codex/`, `.cursor/`), plus logs, caches, archives, reports, and
release artifacts.

**Why this improves alignment.** The enumeration matches the packet's own
storage-class analysis (README confirmed evidence names state, generated,
inputs, and host-projection surfaces; the implementation-plan validation plan
already tests raw intake, archives, extension source, ideation, proposals,
plans, syntheses, reports, state, generated, and host projections). AC-01 is
now deterministically checkable: a reviewer can compare the delivered posture
matrix against a closed root list instead of judging what counts as "major".
