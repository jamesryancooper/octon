Constitutional and current durable repository authority outrank this packet.
`proposal.yml` controls identity/lifecycle, `architecture-proposal.yml` subtype,
`resources/trust-activation-design-and-dependency-receipt.yml` the exact
mechanisms, `resources/packet-contract.yml` the RP-09 planning boundary, and architecture
documents the planned design and proof. The catalog and proposal registry are
projections. The intake controls accepted operator-intent lineage while
remaining non-authoritative pending promotion; reconciliation controls the
RP-09 packet boundary, engineering refinement, and proof sequence without
reopening accepted intent. Planned proof remains `UNVERIFIED`.

RP-01 alone issues activation authority and owns authority-epoch semantics.
RP-09 contributes a strict consumer-binding schema and negative fixtures only;
it cannot issue, default, widen, renew, sign, or self-satisfy an activation
envelope. The exact JCS/SHA-256 inventory and version manifests, immutable
install layout, two-slot selector journal, bootstrap receipt, health/rollback
profile, retention pins, dependency digests, and proof order are selected in
the design receipt. They are planned-not-installed-not-activated.
