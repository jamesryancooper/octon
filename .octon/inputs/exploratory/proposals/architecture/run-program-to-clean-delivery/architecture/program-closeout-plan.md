# Program Closeout Plan

Parent closeout may run only after all required child packets have current
child-owned closeout evidence or explicit blocked/deferred outcomes accepted by
their owning routes.

Closeout must refresh route-owned parent and child navigation, artifact
catalogs, generated proposal registry, artifact indexes, spines, and handoff
capsules through canonical generators where required. Generated metadata remains
derived-only and non-authoritative.

Parent closeout may aggregate child state but cannot satisfy child receipts,
promotion targets, validation verdicts, archive metadata, delivery evidence, or
terminal clean-state proof.
