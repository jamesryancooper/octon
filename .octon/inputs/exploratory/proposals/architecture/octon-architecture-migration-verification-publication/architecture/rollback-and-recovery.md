# Rollback And Recovery

## Rollback Objective

Rollback disables autonomous publication, preserves candidate work, retains
protected PR for valid policy-selected work, and maintains one authority,
one attempt store, one broker, and one physical Git effect path. It never
restores candidate verification, ambiguous context trust, direct-main, or
shared verifier/publisher credentials.

## Before Provider Binding

- Disable or remove the shadow verifier and route adapter.
- Retain schema and comparison evidence needed to diagnose the failure.
- Leave current production protection unchanged and autonomous Class B off.
- No provider reconciliation is required because no check or effect changed.

## After Scratch Check Binding

- Remove the scratch required-check binding.
- Revoke or detach the narrow verifier identity from the scratch target.
- Preserve all exact verdicts, producer observations, ruleset observations,
  and candidate commits.
- Restore only a previously certified verifier version behind the same
  authenticated identity and permission boundary.

## After Route Installation

- Disable the autonomous publication feature or route immediately.
- Keep protected PR available only for valid work selected by the frozen
  policy.
- Preserve candidate outputs and RP-03 operation/attempt facts.
- Reconcile any sent RP-05 effect through RP-08 semantics before retry.
- Never reinterpret invalid authority as a PR fallback.

## Provider Drift Or Outage

Drift in rulesets, required-check producer, App identity/permissions,
environments, secret consumers, workflow projection digest, or audit binding
disables or demotes the affected route. Candidate work remains available,
safe Class A continues, and valid review-required work may use protected PR.
No stale provider observation or context name substitutes for fresh proof.

## Verifier Failure

Missing, conflicting, expired, revoked, or unavailable verdicts block only
publication. The publisher cannot self-verify, the broker cannot mint a
verdict, and the operator is not asked to approve the effect through a
routine prompt. Recovery deploys only the prior certified verifier under the
same immutable identity contract or keeps the route disabled.

## Projection Failure

If source/output digests diverge or the accepted .octon generator is absent,
disable affected projected checks/workers or return to the last receipted
projection. Do not repair by editing .github directly. Retain source digest,
output digest, publisher identity, generation receipt, and drift result.

## Rollback Evidence

Retain verifier identity/version, permission disposition, verdict and policy
digests, provider configuration snapshot, projection source/output digests,
route-disable action, affected operations, candidate preservation proof, and
the last certified verifier or projection restored.

## Recovery Success

Recovery succeeds when autonomous publication is disabled or the exact prior
certified verifier/policy/projection boundary is restored, candidate work is
preserved, and no unresolved effect is retried. Provider availability alone
is not recovery proof.

Rollback preserves `O`, `S`, `V`, route, history, operation/attempt, and every
provider observation. Target/base/head movement invalidates the tuple and
requires a fresh pre-effect decision; it never changes the frozen attempt to
PR. Mirror failure leaves hosted landed proof intact. Cleanup failure preserves
the source candidate and reports `landed/cleanup-deferred`, never `cleaned`.
