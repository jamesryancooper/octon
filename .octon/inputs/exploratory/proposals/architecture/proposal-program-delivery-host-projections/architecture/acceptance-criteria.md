# Acceptance Criteria

- `.codex` projections exist for accepted proposal delivery wrapper surfaces or are explicitly narrowed with evidence.
- Each projection cites a canonical `.octon` source.
- Each projection states that it is non-authoritative and cannot authorize lifecycle transitions.
- Projection names and descriptions match the accepted delivery input contract.
- Product catalog coherence is handled by an `.octon`-scoped child and is not silently widened by this repo-local child.
- Parent program evidence does not satisfy this child acceptance criteria.
