# Target Architecture

Validation and documentation should cover:

- advisory-only report behavior;
- authority boundaries for review, validation, closeout, archive, cleanup, and terminal proof;
- uncertainty interpretation;
- recommended follow-up routes for governance changes;
- examples of automation, batching, caching, and risk-based recommendations;
- rejection cases where evaluator output is used as a gate receipt.

The documentation should help operators improve governance efficiency without weakening the governance model.
