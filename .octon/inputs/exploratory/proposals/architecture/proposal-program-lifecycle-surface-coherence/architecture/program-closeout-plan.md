# Program Closeout Plan

Parent closeout is allowed only after every required child has reached an allowed terminal outcome through its own lifecycle route.

## Required Child Outcomes

- `proposal-delivery-input-contract-alignment` must close with child-owned evidence that delivery input contracts are coherent or that rejected/superseded work is explicitly recorded.
- `proposal-program-delivery-host-projections` must close with child-owned evidence that host projections and product catalog claims are coherent or explicitly narrowed.
- `proposal-program-delivery-operator-alias` must close with child-owned evidence that any alias delegates to canonical delivery without authority widening, or that the alias was intentionally rejected as optional.
- `proposal-program-review-loop-documentation` must close with child-owned evidence documenting the program review/revision decision and preserving child authority boundaries.
- `proposal-lifecycle-surface-validation-hardening` must close with child-owned evidence that coherence checks cover the final accepted surface set.

## Aggregate Parent Evidence

Before parent archival, parent-local aggregate receipts must show:

- parent program structure validation passed;
- child registry, human index, sequence, child contract, and closeout plan remained synchronized;
- every required child terminal outcome is current and child-owned;
- aggregate verification and correction receipts have `child_authority_preserved: yes`;
- cleanup disposition is explicit and does not authorize deletion by detection alone;
- archive handoff cites child-owned evidence by reference instead of copying authority;
- terminal proof cites retained validation or run evidence when implementation routes require retained evidence.

## Refusal Conditions

Refuse parent closeout or archive when:

- any required child remains non-terminal without explicit deferral, rejection, supersession, or replacement evidence;
- a parent artifact attempts to satisfy a child receipt or child validation verdict;
- generated projection freshness is stale but used as proof;
- product catalog claims outstate available commands or skills;
- cleanup residue is detected without an owning cleanup route and evidence disposition;
- validation coverage does not include the accepted lifecycle surface set.
