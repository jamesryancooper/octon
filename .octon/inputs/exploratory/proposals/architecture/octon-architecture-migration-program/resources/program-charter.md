# Program Charter

## Mission

Coordinate the fixed reconciled architecture into fifteen independently
reviewable packets that materially improve solo-developer autonomous completion,
delivery speed, safety, simplicity, recovery, and maintenance burden without
creating a second control plane or weakening current authority.

## Scope

The parent owns the child index/DAG, sequence, cross-packet ownership,
safe-state/risk/evidence read models, operator reading order, correction routing,
program verification, promotion handoff, and aggregate closeout. Children own
all implementation and lifecycle authority.

The governing publication decision is candidate-first: Class A remains local;
eligible admitted Class B defaults to `brokered-class-b-no-pr`; valid
review-required or deterministically preclassified high-contention Class B uses
protected PR; Class C uses stronger control or denial. Invalid, stale, revoked,
mismatched, raced, or unknown authority denies and preserves work. Octon owns no
human or agent `direct-main`; canonical local `main` is a post-publication mirror.

## Non-Goals

No migration execution, proposal acceptance, authority/support/trust promotion,
provider mutation, Git publication, public marketplace, enterprise platform,
distributed consensus, VM fleet, persistent agent organization, Octon-owned
direct-main route, credentialed candidates, universal PR, multi-writer state, or universal
exactly-once claim is authorized.

## Decision Baseline

The intake is the non-authoritative record of accepted operator intent pending
formal promotion. The independent reviews and complete reconciliation may sharpen
current findings, packet boundaries, engineering defaults, migration sequencing,
and proof, but may not silently reopen accepted intent. A settled decision may be
reopened only by new evidence of implementation impossibility, contradiction,
material safety failure, or a materially simpler alternative that preserves every
accepted invariant.

The reconciliation's fifteen-packet graph and fourteen-workgroup dependency spine
remain the controlling non-authoritative coordination baseline. Packet boundaries
cannot be merged, split, omitted, or renumbered without the same governed evidence
and smallest-safe-alternative analysis.

## Five Value Milestones

1. Contained and truthful: RP-00.
2. Useful safe candidate foundation: RP-01–RP-04 plus RP-10/RP-11 branch.
3. Fast verified delivery: RP-05–RP-06.
4. Recoverable trustworthy autonomy: RP-07–RP-09.
5. Complete bounded solo product and promotion proof: RP-12–RP-14.

## Lifecycle Milestones

The historical creation milestone was satisfied when the sixteen draft packets
validated structurally, the registry was fresh, child authority was preserved,
Revision 2 was unchanged, and the program became ready for operator review.
That creation milestone alone was not implementation readiness.

Pre-implementation readiness requires fresh accepted reviews for all fifteen
required children and this parent, strict architecture receipts, exact
scope/DAG/ownership/collision coherence, passing parent and child-readiness
gates, and a fresh canonical digest-bound program implementation-orchestration
prompt. Reaching that milestone authorizes only a separate future implementation
run; it does not itself implement, prove, promote, publish, or close any child.
