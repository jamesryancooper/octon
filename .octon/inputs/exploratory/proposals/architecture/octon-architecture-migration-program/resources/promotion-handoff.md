# Promotion Handoff

RP-14 produces an evidence-only claim map and handoff. It never changes runtime,
workflow, CLI, validator, provider, support, release, roadmap, or trust authority.
Passing claims are submitted to the separately governed owning promotion route;
failed/stale claims are demoted and returned to the child owner.

Before privileged implementation: RP-00 containment and understood
authority/credential boundaries. Before Class B publication: RP-01–RP-08
complete grant, `O/S/V`, exact CAS, history, route freeze, substantive
validation, protected-PR `S -> Q`, provider subeffect, idempotency,
reconciliation, signature, capacity, mirror, cleanup, preservation, and rollback
proof. PR must be policy-selected, never a failure fallback. Before trust
activation: the accepted ROD-003 content-addressed
epoch-zero inventory, one-time human anchor, exact bounded preauthorization,
RP-09 previous-version exact activation, health, rollback, and no same-change
rule-modification proof. Actual safe-automatic enablement remains a later
claim-scoped acceptance after proof.

ROD-006 is accepted as no Octon-owned direct-main route; RP-00 must encode and
prove it. It does not impose a universal PR route or govern support promotion.
Before support promotion:
claim-scoped dogfood,
the full proof matrix, current provider observation, burden budgets, downstream
owner review/authorization, and exact core or optional claim disposition. Failed,
stale, or incomplete extension, child, provider, or safe-automatic proof leaves
that claim disabled/unclaimed. Before implemented archive: all child promotions,
conformance/drift/closeout, parent aggregate verification, and terminal archive
receipts.
