# Implementation Plan

## Step 1: Define Accepted Surface Matrix

Build a fixture or manifest that lists accepted packet/program lifecycle commands, skills, workflows, contracts, prompt bundles, projections, product catalog entries, and docs.

## Step 2: Add Coherence Validators

Add scripts or tests that compare the accepted surface matrix against current repo files.

## Step 3: Add Refusal Fixtures

Add negative controls for missing required inputs, stale host projection claims, parent-as-child receipt substitution, cleanup without authority, archive handoff without child evidence, and terminal proof without retained evidence.

## Step 4: Add Product Catalog Checks

Ensure product catalog claims for proposal delivery do not outstate canonical sources or host projections.

## Step 5: Record Evidence

Record child-owned implementation, conformance, drift/churn, closeout, and validation evidence.
