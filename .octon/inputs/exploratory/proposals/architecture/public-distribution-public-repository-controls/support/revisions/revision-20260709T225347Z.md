## AR-002: Registry Deliverables Named Explicitly In Architecture Docs

## AR-005: PD-025 Ownership Moved; AC-01 Rewritten As Consumer

- **Previous position:** AC-01 read: "The portable export labels every path as installable or public-repository-only, and downstream installation excludes the latter." The README adopted-decision bullet read: "Public-repository-only files are classified separately from installable content," and the README scope bullet read: "Separate public-repository-only files from downstream-installable content." The packet carried no explicit decision-ownership list, leaving it implied that this packet defined the labels.
- **Revised position:** AC-01 now states that this packet consumes the installable/public-repository-only labels defined by the `public-distribution-portable-dropin-export` export manifest, assembles public-repository-only content exclusively from paths so labeled, and verifies that no assembled path is unlabeled or relabeled here. The README bullets were updated to the consumer framing, the target-architecture Deterministic Automation bullet now verifies assembled content against the export manifest's labels, and the target-architecture Ownership section now records that this packet owns PD-003, PD-009, PD-011, PD-013, PD-016, PD-017, PD-021, and PD-022 while PD-025 is owned by `public-distribution-portable-dropin-export`.
- **Why this improves alignment:** Parent traceability moved PD-025 ownership to the portable-dropin export packet. The old AC-01 asserted an acceptance test over another packet's deliverable, which would have created dual ownership of the label definition and an unverifiable criterion inside this packet's write scopes.

## AR-007 (Partial): Rollback Section Sharpened By Reversibility Class

- **Previous position:** `architecture/implementation-plan.md` Rollback And Interrupted Operation was four undifferentiated bullets: an operation log with compensating actions for reversible settings, discarding failed imports, deleting bad drafts, and a bare pointer that immutable assets are withdrawn or superseded "according to the runbook" without defining it.
- **Revised position:** The section now enumerates three classes: (1) the reversible class — repository settings, branch and tag rulesets, Actions permissions, secret-scanning and push-protection toggles, and vulnerability-reporting settings — each with its compensating operation (reapply the logged prior value through the plan-then-apply path), plus pre-merge import discard and draft deletion; (2) the irreversible class — published immutable releases, their assets, and protected tags; and (3) an explicit withdraw-or-supersede runbook for the irreversible class: mark withdrawn in release notes without altering assets, publish a superseding release through the same verification and publication gates, repoint advisories and documentation, and record a maintainer decision receipt.
- **Why this improves alignment:** The parent registry declares this child's rollback posture as compensating; the packet must therefore state exactly which operations have compensations and which do not. Making publication the explicitly named one-way transition with a concrete withdraw/supersede procedure removes the previously undefined "runbook" reference.
